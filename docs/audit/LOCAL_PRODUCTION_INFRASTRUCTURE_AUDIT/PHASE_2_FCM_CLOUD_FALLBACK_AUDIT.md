## 1. Executive Summary

This independent audit assesses the complete source-level implementations of **Firebase Cloud Messaging (FCM)** background wake-up notifications and **Cloud Media Fallback** across the NEXA Go backend and Android client application.

### Key Audit Findings

1. **FCM Backend Authentication — Critical Gap (`getAccessToken()` returns empty string):**
   - In [`backend/internal/fcm/fcm_service.go:111–115`](file:///H:/chat_app/backend/internal/fcm/fcm_service.go#L111-L115), `getAccessToken()` returns an unpopulated private field `s.accessToken`.
   - The Go backend contains **zero Google Service Account OAuth2 token exchange logic** (no RS256 JWT generation, no exchange at `https://oauth2.googleapis.com/token`).
   - If `FCM_PROJECT_ID` is set, calls to FCM v1 HTTP API (`https://fcm.googleapis.com/v1/projects/%s/messages:send`) fail with **HTTP 401 Unauthorized** due to missing/empty authorization headers.
   - If `FCM_PROJECT_ID` is unset (default), the service silently operates in mock mode, logging simulated wake-up pings.
2. **Android FCM Integration — Missing Client SDK:**
   - `com.google.firebase:firebase-messaging` is **missing** from [`app/build.gradle.kts`](file:///H:/chat_app/app/build.gradle.kts).
   - No `FirebaseMessagingService` subclass exists.
   - No `google-services.json` configuration file is present in `app/`.
   - `NexaPushWakeUpReceiver.kt` listens only for internal local broadcasts (`com.nexa.app.PUSH_WAKE_UP`), leaving Android with no connection to real Google push notifications.
3. **Device Token Registration Lifecycle — Partially Implemented:**
   - Backend endpoint `POST /api/v1/devices/fcm-token` is functional, saving device tokens to PostgreSQL (`devices.fcm_token`).
   - Android has `AuthApiService.updateFcmToken` and `NexaPushManager.onNewPushToken`, but because Firebase SDK is not integrated, real device tokens are never generated by the OS.
   - Device revocation on backend safely clears tokens (`fcm_token = ''`), but Android client logout does not explicitly unregister the push token before clearing session state.
4. **Push Notification Privacy — 100% Zero-Plaintext Rule Preserved:**
   - Payloads are strictly generic wake-up signals: `{ "data": { "type": "WAKE_UP", "timestamp": "..." } }`.
   - Never contains message text, sender identity, recipient phone, private keys, or conversation identifiers.
5. **Cloud Media Fallback — Implemented & Verified:**
   - Backend endpoints `POST /api/v1/media/upload-ticket` and `POST /api/v1/media/purge-ack` are fully functional in [`backend/cmd/server/main.go:347–467`](file:///H:/chat_app/backend/cmd/server/main.go#L347-L467) with 100 MB ceiling gate, IDOR protection, and immediate purge ACK.
   - Android client service [`R2MediaFallbackService.kt`](file:///H:/chat_app/app/src/main/java/com/nexa/app/data/remote/media/R2MediaFallbackService.kt) client-encrypts files via AES-256-GCM ([`BlindMediaVaultEngine.kt`](file:///H:/chat_app/app/src/main/java/com/nexa/app/core/media/BlindMediaVaultEngine.kt)) and handles 4.5s ICE circuit breaker fallback ([`MediaRoutingCoordinator.kt`](file:///H:/chat_app/app/src/main/java/com/nexa/app/core/media/MediaRoutingCoordinator.kt)).
   - Backend upload URL generation currently uses a placeholder R2 endpoint pattern rather than AWS S3 v4 presigned URL generation with Cloudflare R2 credentials.

## 2. FCM Backend Authentication Audit

### 2.1 Code Inspection (`backend/internal/fcm/fcm_service.go`)
- **Initialization (Lines 28–43):**
  ```go
  func NewFcmService() *FcmService {
      projectId := os.Getenv("FCM_PROJECT_ID")
      isMock := projectId == ""
      ...
  }
  ```
  If `FCM_PROJECT_ID` is not set, `s.isMock` is true, and the service bypasses external HTTP requests.
- **Dispatch Logic (Lines 46–98):**
  ```go
  url := fmt.Sprintf("https://fcm.googleapis.com/v1/projects/%s/messages:send", s.projectId)
  ...
  if token := s.getAccessToken(); token != "" {
      req.Header.Set("Authorization", "Bearer "+token)
  }
  resp, err := s.httpClient.Do(req)
  ```
- **Access Token Getter (Lines 111–115):**
  ```go
  func (s *FcmService) getAccessToken() string {
      s.mu.RLock()
      defer s.mu.RUnlock()
      return s.accessToken
  }
  ```

### 2.2 Investigation of `getAccessToken()` Defect
1. **Root Cause:** `s.accessToken` is declared on `FcmService` struct, but **is never set anywhere in the codebase**. There is no constructor logic, background worker, or token refresher that assigns to `s.accessToken`.
2. **Missing OAuth2 Service Account Flow:**
   - To authenticate with Google FCM v1 API, the server must hold Google Service Account JSON credentials containing `client_email`, `private_key_id`, and RSA `private_key`.
   - The server must sign a JWT assertion (claim set: `iss` = service account email, `scope` = `https://www.googleapis.com/auth/firebase.messaging`, `aud` = `https://oauth2.googleapis.com/token`, `exp` = 1 hour).
   - The server must POST the assertion to `https://oauth2.googleapis.com/token` to receive an OAuth2 Bearer access token, cache it safely with read-write mutex synchronization, and refresh it before expiry.
3. **Real-World Impact:**
   - In development: Server defaults to mock mode (`FCM_PROJECT_ID=""`), so errors are not thrown, masking the defect.
   - In production: Setting `FCM_PROJECT_ID` causes `SendWakeUp` to execute HTTP calls without an `Authorization` header, immediately failing with `HTTP 401 Unauthorized` (`FCM API returned error status: 401`).
4. **Classification:** **FAILED / NOT IMPLEMENTED (Token Exchange)**.

## 4. Token Registration & Lifecycle Audit

### 4.1 Token Registration Flow
1. Android client acquires FCM token via Firebase SDK (`FirebaseMessaging.getInstance().token`). *(Missing)*
2. Client sends token to Go backend via `POST /api/v1/devices/fcm-token` with Bearer session token. *(Implemented in `AuthApiService.kt:276` and `AuthHandler.go:826`)*.
3. Backend validates session, binds token to caller's `device_id`, and stores it in PostgreSQL:
   ```sql
   UPDATE devices SET fcm_token = $2, last_active_at = $3 WHERE device_id = $1
   ```
   *(Implemented in `PostgresRepository.UpdateDeviceFcmToken`)*.

### 4.2 Token Detachment & Revocation
- **Device Revocation:** When a device is revoked (`POST /api/v1/devices/{device_id}/revoke`), the backend executes:
  ```sql
  UPDATE devices SET is_revoked = TRUE, fcm_token = '' WHERE device_id = $1
  ```
  *(Verified in `backend/internal/database/repository.go:377`)*. The revoked device immediately stops receiving wake-up pings.
- **User Logout:** In `MainChatDashboardScreen.kt`, logout calls `authRepository.clearSession()` and `chatRepository.stopConnection()`. It does **not** make an explicit call to clear `devices.fcm_token` on the backend before clearing local credentials, leaving the device token active until replaced or revoked.
- **Classification:** **PARTIALLY VERIFIED**.

## 7. E2EE and Media Privacy Verification

The complete 12-step file transfer lifecycle was audited:

```
[1. File Selection] 
        │
[2. Local Validation] (<= 100 MB ceiling check)
        │
[3. Blind Client Encryption] (AES-256-GCM, single-use 256-bit Key + 96-bit IV)
        │
[4. SHA-256 Cipher Hash Computation]
        │
[5. P2P Direct Attempt] (Priority 1: 4.5s ICE Gathering Gate)
        │
   ┌────┴─────────────────────────────┐
   ▼ (Success)                        ▼ (ICE Failure / CGNAT / Peer Offline)
[Direct WebRTC DataChannel]    [6. Request Upload Ticket] (Go Backend)
                                      │
                               [7. Encrypted .enc Upload] (Cloudflare R2 Mailbox)
                                      │
                               [8. Send E2EE Envelope] (Double Ratchet Wire Packet:
                                    Contains MediaKey, IV, ObjectKey, CipherHash)
                                      │
                               [9. Recipient Downloads .enc Blob]
                                      │
                               [10. Verify SHA-256 Cipher Hash]
                                      │
                               [11. Client-Side AES-GCM Decryption]
                                      │
                               [12. POST /api/v1/media/purge-ack]
                                    (Immediate Object Purge, 0 Bytes Retained)
```

- **Ciphertext-Only Storage:** Verified. The cloud object storage receives exclusively `.enc` files.
- **Key Isolation:** Verified. Media keys and IVs are transported exclusively inside Double Ratchet encrypted envelopes. The backend and R2 storage never have access to decryption keys.
- **Tamper Resistance:** Verified by unit tests: tampered ciphertext fails GCM authentication tag verification, preventing corrupted file saves.
- **Classification:** **VERIFIED**.

## 8. P2P-to-Cloud Fallback Decision Logic

Inspected [`MediaRoutingCoordinator.kt`](file:///H:/chat_app/app/src/main/java/com/nexa/app/core/media/MediaRoutingCoordinator.kt):
1. **Rule D (&le; 64 KB):** Small media (voice notes, thumbnails) embeds directly into WebSocket envelope (`INLINE_E2EE_WEBSOCKET`).
2. **Rule B (Group Chats):** Multi-recipient media uploads once to Cloudflare R2 Blind Fallback to prevent mobile sender battery and bandwidth exhaustion.
3. **Offline Recipient:** When peer presence is offline, transfer routes directly to Cloudflare R2 Mailbox (7-day auto-purge TTL).
4. **Online Direct 1-to-1:** Priority 1 WebRTC P2P DataChannel.
5. **4.5-Second Circuit Breaker:** `executeWithIceCircuitBreaker()` enforces a strict 4500ms timeout on ICE candidate gathering. If connection hangs or fails due to Carrier Symmetric CGNAT, it immediately trips the circuit breaker and falls back to R2.
- **Classification:** **VERIFIED**.
